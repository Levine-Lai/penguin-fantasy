# 恢复与撤回

## 未提交修改

先 `git status` 和 `git diff` 确认内容；不要用 reset --hard 或批量清理删除旧工作。本次旧分支的七个文件已保存为本地分支 `codex/archive-ui-ledger-stage-20261104` 的提交 `236fb5b`。需要时用 `git show 236fb5b -- 文件路径` 查看，再逐文件恢复；不要把整个旧版本覆盖到 main。该备份目前仅在本机，应另行备份磁盘以防设备损坏。

## 已上线的前端

从最新 main 新建修复分支，对引入问题的普通提交运行 `git revert <提交SHA>`，保留撤回记录。若是合并提交，应先检查父节点，再决定使用哪一条主线。通过 `npm run verify`、PR 合并，再按 AGENTS.md 把同一新提交发布到两个站点，运行 `npm run verify:online`。前端回退不会回退 API 或报名数据。

## Worker 与正式数据

Worker、D1、KV 与静态网页有独立生命周期。修改 Worker 时记录部署版本，修改 D1 前先按 Cloudflare 官方 D1 导出流程做本地备份，并将文件放在 `.private/` 或 `outputs/`。数据库回退可能丢失备份后的报名，必须先检查受影响记录并说明恢复范围；优先做针对性的修复。不要为了撤销一个前端样式回滚数据库。

## 发布失败

检查 GitHub Actions 失败步骤；测试/构建失败禁止继续发布。若 GitHub 已成功而 Cloudflare 失败，保留已经成功的提交，修复登录或部署问题后继续同一 SHA，不另改业务代码绕过检查。最终明确报告哪一端成功、哪一端失败。
